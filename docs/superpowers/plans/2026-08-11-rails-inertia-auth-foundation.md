# Rails + Inertia Auth Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a new Rails app (in `rails/` inside this repo) that serves an Inertia+React frontend with a working Devise-backed password login/logout flow, proving the session works end to end.

**Architecture:** A fresh Rails 8 app lives at `rails/` alongside the existing `src/` (Next.js) and `supabase/` directories, sharing this repo's git history. Rails serves React/TypeScript pages via `inertia_rails` + Vite. Devise (`database_authenticatable`, `validatable` only) backs a single `User` model with a `role` enum. A custom `SessionsController` subclasses `Devise::SessionsController` so login/logout render Inertia responses instead of Devise's default ERB views.

**Tech Stack:** Rails 8.x, Ruby 3.3+, PostgreSQL (local, UUID primary keys), Devise, `inertia_rails`, `vite_rails`, React 19 + TypeScript, RSpec + FactoryBot.

## Global Constraints

- New Rails app lives at `rails/` inside this existing repo (not a separate repo).
- Rails 8.x, Ruby 3.3+.
- Fresh local Postgres database, distinct from the existing Supabase Postgres instance.
- Every table uses a UUID primary key, via Postgres's built-in `gen_random_uuid()` (Postgres 13+ — no `pgcrypto`/`uuid-ossp` extension needed).
- Frontend: `inertia_rails` serving React 19 + TypeScript pages, bundled with `vite_rails`.
- Auth: Devise, with only `:database_authenticatable` and `:validatable` modules enabled — no registerable/recoverable/rememberable/confirmable in this spec.
- Testing: RSpec + FactoryBot. Request specs only — no system/feature (headless browser) specs in this spec.
- Local dev only. No hosting provider, CI/CD, or Dockerfile in this spec.
- `role` enum values are exactly `admin`, `sales`, `client` (matches the existing Supabase `user_role` enum's values).

RSpec.describe "Sessions", type: :request do

    expect(response.body).to include("data-page")

  it "redirects an already-authenticated visitor away from the login page" do

- [ ] **Step 3: Add the SessionsController**

Create `rails/app/controllers/sessions_controller.rb`:

```ruby
class SessionsController < Devise::SessionsController
  def new
    render inertia: "Auth/Login", props: { errors: {} }
  end

  def create
    self.resource = warden.authenticate!(auth_options)
    sign_in(resource_name, resource)
    redirect_to dashboard_path
  rescue Warden::NotAuthenticated
    redirect_to new_user_session_path, inertia: { errors: { base: "Invalid email or password" } }
  end

  def destroy
    sign_out(resource_name)
    redirect_to new_user_session_path
  end

  # Devise's default require_no_authentication before_action (runs on #new)
  # redirects here when someone already signed in visits the login page.
  # The default implementation falls back to root_path, which is this same
  # login page, causing a redirect loop — so it must resolve to the
  # dashboard instead.
  def after_sign_in_path_for(resource)
    dashboard_path
  end
end
```

- [ ] **Step 4: Add the Login page**

Create `rails/app/javascript/pages/Auth/Login.tsx`:

```tsx
import { useForm } from '@inertiajs/react'
import { FormEvent } from 'react'

interface Props {
  errors: { base?: string }
}

export default function Login({ errors }: Props) {
  const { data, setData, post, processing } = useForm({
    email: '',
    password: '',
  })

  function handleSubmit(e: FormEvent) {
    e.preventDefault()
    post('/users/sign_in')
  }

  return (
    <form onSubmit={handleSubmit}>
      {errors.base && <p role="alert">{errors.base}</p>}
      <input
        type="email"
        value={data.email}
        onChange={(e) => setData('email', e.target.value)}
      />
      <input
        type="password"
        value={data.password}
        onChange={(e) => setData('password', e.target.value)}
      />
      <button type="submit" disabled={processing}>Log in</button>
    </form>
  )
}
```
