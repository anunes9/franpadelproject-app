# Courses Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the Courses feature off the hardcoded `DashboardData::MODULES` / `DashboardData::MODULE_1_SECTIONS` constants onto two real tables — `course_modules` (admin-manageable content) and `user_module_progresses` (per-user status/progress) — without changing any frontend prop shape except one defensive line in `Home.tsx`.

**Architecture:** Two new ActiveRecord models (`CourseModule`, `UserModuleProgress`), a `CourseModule.dashboard_list_for(user)` batching helper that merges content with a user's progress into the exact JSON shape the frontend's `Module` type already expects, an ActiveAdmin resource for content editing, and a seed script importing the real bilingual content export (`docs/courses/beginner.json`, using its `pt` fields) instead of the hand-typed `DashboardData` constant.

**Tech Stack:** Rails 8.1, PostgreSQL (uuid primary keys via `gen_random_uuid()`), RSpec + FactoryBot, ActiveAdmin, Inertia Rails + React/TypeScript frontend (untouched except one line).

## Global Constraints

- Every table uses a uuid primary key (`config/application.rb:45`: `g.orm :active_record, primary_key_type: :uuid`) — `create_table ..., id: :uuid` with no explicit `default:` needed; Rails/Postgres fills in `gen_random_uuid()` automatically (see `db/migrate/20260811185942_devise_create_users.rb` and its `db/schema.rb` output).
- Enum syntax follows `app/models/user.rb:7`: `enum :name, { key: 0, ... }` (positional symbol + hash, no `default:` keyword — the DB column's `default:` is what actually determines the default value).
- Any model exposed to ActiveAdmin filters/search needs `ransackable_attributes` / `ransackable_associations` class methods (Rails 7.1+ Ransack safelist), matching `app/models/user.rb:9-15`.
- ActiveAdmin enum filters must submit the enum's integer value, not its string key, per the documented Ransack gotcha in `app/admin/users.rb:16-19` (`filter :role, as: :select, collection: -> { User.roles.to_a }`) — the same pattern applies to `level`.
- Spec style: `RSpec.describe X, type: :model` / `type: :request`, `FactoryBot` via `create`/`build` (no `FactoryBot.` prefix — `config.include FactoryBot::Syntax::Methods` in `spec/rails_helper.rb`), `sign_in` from `Devise::Test::IntegrationHelpers` for request specs.
- No new frontend files or type changes — `app/frontend/types/dashboard-data.ts`, `ModuleCard.tsx`, `Courses/Index.tsx`, `Courses/Show.tsx`, `Courses/Quiz.tsx` are all untouched. Controllers must keep emitting the exact same prop shapes they do today.
- Exercises and Quiz stay exactly as they are — hardcoded in `DashboardData`, not persisted, not touched by this plan.
- Full design context: `docs/superpowers/specs/2026-08-13-courses-module-design.md`.

`app/models/course_module.rb`:
```ruby
class CourseModule < ApplicationRecord
  enum :level, { beginner: 0, intermediate: 1, advanced: 2 }

  has_many :user_module_progresses, dependent: :destroy

  validates :slug, :title, :description, :duration, presence: true
  validates :slug, uniqueness: true

  scope :ordered, -> { order(:level, :position) }

  def topics_text
    topics.join(", ")
  end

  def topics_text=(value)
    self.topics = value.to_s.split(",").map(&:strip).reject(&:blank?)
  end

  def sections
    return [] if content.blank?

    content.split(/^## /).reject(&:blank?).map do |chunk|
      heading, *rest = chunk.strip.lines.map(&:strip)
      items = rest.select { |line| line.start_with?("- ") }.map { |line| line.delete_prefix("- ") }
      { heading: heading, items: items }
    end
  end

  def as_dashboard_json(progress = nil)
    {
      id: slug,
      n: position,
      title: title,
      description: description,
      topics: topics,
      duration: duration,
      level: level.capitalize,
      status: progress&.status || "locked",
      progress: progress&.progress || 0
    }
  end

  def self.dashboard_list_for(user)
    modules = ordered.to_a
    progresses = UserModuleProgress.where(user: user, course_module_id: modules.map(&:id))
                                    .index_by(&:course_module_id)
    modules.map { |m| m.as_dashboard_json(progresses[m.id]) }
  end

  def self.ransackable_attributes(_auth_object = nil)
    %w[slug title description level position duration created_at updated_at]
  end

  def self.ransackable_associations(_auth_object = nil)
    []
  end
end
```
